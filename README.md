# ГП — ежедневное случайное название Discord-сервера

Генерирует **ровно два слова**: первое на Г, второе на П. Согласует
прилагательное с существительным по роду и числу в именительном падеже,
отсекает названия с подстрокой «гей» и меняет имя сервера каждый день.

Например: «Гомосексуальная петрушка», «Говно помойное»,
«Голодный пельмень», «Грустные пельмени».

## Настройка — один раз

1. Откройте https://discord.com/developers/applications и создайте `New Application`.
2. Перейдите в **Bot**, создайте/активируйте бота и получите **Token** через `Reset Token`/`Copy` (что доступно в интерфейсе). **Никому не отправляйте этот токен и не добавляйте в файлы репозитория.**
3. В **Installation** или **OAuth2 → URL Generator** создайте ссылку на добавление бота, включив `bot` и разрешение **Manage Server / Управлять сервером**. Добавьте бота на нужный сервер. Администраторские права не нужны. Установкой бота должен заниматься человек с правом управления сервером.
4. В Discord включите **Режим разработчика** (Настройки → Расширенные), щёлкните правой кнопкой по серверу → **Копировать ID сервера**.
5. Создайте новый репозиторий на GitHub (лучше **Private**) и загрузите туда всё содержимое этой папки, **включая скрытую папку `.github`**. Workflow должен находиться в основной ветке (обычно `main`).
6. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Добавьте:
   - `DISCORD_BOT_TOKEN` — токен Discord-бота;
   - `DISCORD_GUILD_ID` — числовой ID сервера Discord.
7. GitHub → **Actions → Ежедневное название ГП → Run workflow**. Это немедленно проверит работу (и изменит название).

После этого GitHub сам запускает скрипт **каждый день примерно в 12:17 по Москве**.
Компьютер держать включённым не требуется, как и оплачивать постоянный процесс на VPS.

## Если хотите только посмотреть генератор

Для локального предварительного просмотра нужен Python 3.9+ (рекомендуется 3.12).

```bash
pip install -r requirements.txt
python main.py --preview
```

Команда покажет названия для ближайших 10 дней и **не** будет обращаться к Discord.

## Как менять словари

В `main.py` доступны четыре списка:

- `G_ADJECTIVES` — прилагательные на Г;
- `P_NOUNS` — существительные на П с грамматическим родом;
- `G_NOUNS` — существительные на Г с грамматическим родом;
- `P_ADJECTIVES` — прилагательные на П.

Варианты `прилагательное + существительное` и `существительное + прилагательное`
смешиваются. Для существительных используйте:
`masc` (муж.), `femn` (жен.), `neut` (сред.), `plur` (мн. число).
Все существительные нужно записывать в именительном падеже, а прилагательные —
в мужском роде, единственном числе, именительном падеже. Не используйте
неоднозначные сокращения или многословные элементы.

**Важно:** алгоритм гарантирует грамматическое согласование для корректно
размеченных слов, но не проверяет осмысленность или стилистическую уместность
случайной фразы. Все словари можно редактировать вручную.

## Время и надёжность

- Расписание по умолчанию — `17 9 * * *` (09:17 UTC, 12:17 Москва). Изменить можно в `.github/workflows/daily-rename.yml`.
- Система `TIMEZONE` в workflow определяет, какой местной датой пользуется генератор.
- **GitHub Actions не гарантирует запуск ровно в указанную минуту:** задачи могут задерживаться, а иногда пропускаться.
- **В публичных репозиториях** GitHub отключает запланированные workflows после 60 дней без активности. Поэтому для такого проекта удобнее приватный репозиторий.
- Если нужна высокая надёжность, этот же скрипт можно запускать на VPS через системный `cron`. Например, локально через `crontab -e`:
  `17 12 * * * cd /opt/gp-name-rotator && /opt/gp-name-rotator/.venv/bin/python main.py >> /var/log/gp-rename.log 2>&1`
  (для машины с временем Europe/Moscow; токен и ID должны быть доступны в переменных окружения).
- Discord может отказать в переименовании (недостаточно прав, фильтрация названия, ошибка сети). Причина будет выведена в журнале GitHub Actions.
- При повторной работе по расписанию в один и тот же день выбирается одна и та же фраза. **Ручной запуск через Actions** делает новый выбор.

## Безопасность

Не используйте токен обычного пользовательского аккаунта Discord (self-bot).
Используйте именно **Bot Token** из Developer Portal. Никогда не выкладывайте
его в открытый доступ. Если токен утёк — перевыпустите его в панели Discord.
